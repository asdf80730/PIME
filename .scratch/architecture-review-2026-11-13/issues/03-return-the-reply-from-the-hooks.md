# Return the reply from the hooks instead of accumulating it

Status: resolved
Category: enhancement

摘要：39 個 method 裡 19 個只是寫 `currentReply`；改由 hook 回傳 partial reply、
dispatcher 合併，外部 interface 不變，測試只跨同一個 seam。

## Problem

Nineteen of the 39 methods are two-line writes into the public mutable
`currentReply`, and the dispatcher reads then resets that field after the hook
returns. A hook's result is visible only through the field, so tests reach past
the interface (`test_reply_fields_accumulate_then_reset`, `test_reply_builders`)
and the reset ordering is a fact every caller must learn.

## Solution

Hooks return their partial reply; the dispatcher merges. The external interface
stays `handleRequest(msg) -> reply`, so no caller moves; the setter list becomes
the internal merge table. Pure functions behind the same seam.
