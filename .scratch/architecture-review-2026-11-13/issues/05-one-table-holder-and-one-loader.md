## Problem

The Table holder concept needs twelve files to read: a 64-line base, three
loader classes that differ only in the field they write, and 27 empty
subclasses. Each loader ends in `except Exception: pass`, so a failed load is
unobservable from outside the module.

## Solution

One `TableHolder(kind, files)` with `ensure()` / `wait_until_ready()` /
`reset()` returning the load outcome instead of swallowing it, the existing
`CinTableBase` future as the only state; the empty subclasses become instances
carrying a kind and a file list.

## ADR note

ADR-0003 already settled the shared busy-spin on the Service side. The loader
trio is the upstream-owned part (PR #1004): keep the seam local, and expect
`table_loaders.py` to be deleted rather than grown once #1004 resolves.

## Verification

`tests/test_cintablebase.py` plus `tests/test_chebihua_service.py` stay green;
add one case per load outcome (spawned, loaded, failed) through `ensure()` only.

## Answer

One class, one home: `cinbase.cintablebase.TableHolder` (the holder-concept
module) carries `kind` (`"cin"`/`"rcin"`/`"hcin"`) and `files` as data, keeps
the inherited `CinTableBase.future` as its only state (`loading`/`cin`/`wait`
derived off it), and owns the load policy — `ensure()` returning the exact
`"spawned"`/`"loaded"`/`"failed"` constants without ever raising,
`wait_until_ready()` as the raising seam, `reset()` as the test seam. The
loader trio in `python/cinbase/__init__.py` is untouched, so the C++ reader
and `checkConfigChange` see byte-identical field reads (`future`, `loading`,
`cin`, `wait`, `curCinType` on every kind; `userExtendTable`,
`priorityExtendTable`, `ignorePrivateUseArea`, `selKeys` on the cin kind);
`cbTS.RCinFileNotExist` still lives on the Service.

**Outcome cases** (added to `tests/test_cintablebase.py`, driven through
`ensure()` only; the five prior `CinTableBase` assertions untouched):

- `test_ensure_spawned_starts_one_loader` — fresh holder: first `ensure()`

  table on the Service.
- `test_ensure_loaded_adopts_the_present_table` — done future + matching

  returns `FAILED`, `holder.cin is None`, `service.cin` stays None, nothing
  raises.
- `test_wait_until_ready_raises_on_failed_holder` — same failed holder:
  `TableLoadError` naming `missing.json`.
- `test_reset_is_the_test_seam` — a settled holder clears to pristine; an
  unwaited loader makes `reset(timeout=0.05)` raise `TableLoadError` and
