## Problem

The `client_id|json` request and `PIME_MSG|client_id|json` reply framing, and the
reply key names, are written four times and pinned by five independent suites
with different expectations. No single file states the whole Client ↔ Backend
contract, so a key rename drifts.

## Solution

One committed fixture file — request/reply pairs, one per method name — read by
every adapter's tests in a loop. Four real adapters plus the C++ reader make this
seam worth its keep; the per-language suites shrink to the iteration.

## Verification

Each layer keeps its own runner and must stay green:
`bash tests/run_local_tests.sh python`, `... node`, `... go`, `... rust`. The
fixture is the new source of truth; delete the duplicated literal expectations
the loop replaces.

`docs/adr/0004-per-backend-profile-guids.md`.
