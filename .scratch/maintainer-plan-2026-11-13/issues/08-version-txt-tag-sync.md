## Problem

`v2.0.0-beta4` is `167c0e4`; `upstream/master` sits at `739ed17` with 70 commits
between them, and `version.txt` still reads `2.0.0-beta4`. The installer names its
payload after that file, so the tag and the string the About page prints must move
in the same commit that cuts the tag.

## Answer

Measured on this tree, 2026-11-13:

- `git rev-list --count 167c0e4..739ed17` → `70`.
- `cat version.txt` → `2.0.0-beta4` — the same string the tag names, so the two
  are consistent with each other and only the tag itself is outstanding.

The one-commit shape is therefore: bump `version.txt` and cut the tag on that
commit, in the same push, so `PIME-<version>-setup.exe` from
`tests/build_windows_installer.sh` and the About-page string can never disagree.
Nothing to change in the tree before the freeze lifts: the file already carries
the value the last tag used, and the next release commit moves it with the tag.
